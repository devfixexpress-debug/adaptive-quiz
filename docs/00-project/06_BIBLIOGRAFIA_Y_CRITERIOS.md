# Bibliografía y criterios de diseño

## Tino Reyna Monteverde
Se adopta:
- iniciar en la misión y funciones;
- identificar eventos y parque de datos;
- aplicar análisis semántico;
- separar catálogos/definiciones de instancias reales;
- usar parametrización para estabilidad;
- modelar eventos como fuente de cambios;
- evitar que reglas variables queden rígidamente embebidas.

## Blaha / Rumbaugh
Se adopta:
- concepción del sistema;
- análisis de dominio antes del diseño;
- modelo de clases como estructura estable;
- modelo de estados;
- modelo de interacción;
- diccionario de datos;
- iteración y refinamiento.

## Manual de Modelamiento y Diseño de Base de Datos
Se adopta:
- modelo conceptual, lógico y físico;
- integridad de entidad y referencial;
- restricciones;
- normalización a 3FN como base;
- diccionario de datos.

## Sommerville
Se adopta:
- ingeniería de requisitos;
- diseño arquitectónico;
- diseño OO/UML;
- pruebas;
- gestión de configuración;
- evolución y reutilización.

## Regla de precedencia
Si una decisión de implementación entra en tensión con el modelo de negocio, primero se
preserva la semántica del dominio y luego se optimiza técnicamente.
